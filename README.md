# Aflatoon Suite — DomainSniffer + ServerTester في مشروع واحد (Theos)

© أفلاطون (Aflatoon / Plato) — جميع الحقوق محفوظة.

دylib مستقل واحد يجمع النسختين، بدون Substrate / ElleKit:

1. **DomainSniffer**: يصيد ويعرض النطاقات والـ IP وDNS الخاصة بالتطبيق المضيف،
   مع حجب NextDNS، قواعد الاستبدال، وضع DNS/CHAT/ALL→8.8.8.8، صوت دخول الروم،
   وتسريع صوت المتكلمين.
2. **ServerTester**: اختبار ضغط WebSocket/HTTP لسيرفرك الخاص (العنوان الذي تضبطه بنفسك).
3. **AUTO TEST جديد** داخل شاشة `SERVER TEST`: فحص تلقائي للأهداف التي التقطها
   الـ sniffer، مع خيارين كما طلبت.

## الخياران الجديدان في SERVER TEST

- **ALL (الخيار الأول)**: يصيد **كل** النطاقات والـ IP/DNS التي التقطها الـ sniffer
  ويعمل عليها اختبار تلقائي. لكل هدف: حلّ DNS ثم اتصال TCP مباشر بالمنافذ
  التي رُصدت لها (أو `443` ثم `80`). تُحفظ النتيجة داخل كل سطر
  `🧪 OK/FAIL …ms` وداخل `data.json`.
- **CHAT (الخيار الثاني)**: يصيد فقط **IP وDNS الدردشة والكتابة أونلاين**:
  النطاقات التي تحتوي `chat` / `typing` / `online` / `presence` / `messag` /
  `websocket` / `mqtt` / `xmpp` / `agora` / `sendbird` / `pubnub` / `pusher` /
  `whatsapp` / `telegram` / `discord` وغيرها، إضافة إلى الـ IP التي تعلّمها
  الـ sniffer من حلّ هذه النطاقات، أو الـ IP المرتبطة بأحد هذه النطاقات.
  يختبرها تلقائياً بنفس طريقة `ALL`.

## التشغيل التلقائي

- اختر `ALL` أو `CHAT` في شاشة `SERVER TEST` → يشتغل الاختبار فوراً عند التفعيل،
  ثم كل `N` ثانية (30 / 60 / 120 / 300 / 600) **والتطبيق مفتوح بالمقدمة**.
- `AUTO: كل N ثانية` يغيّر الفاصل. `▶ اختبار الأهداف الآن` يشغّل يدوياً
  (ويعيد اختبار كل الأهداف). `📋 نسخ الأهداف` ينسخ جدولاً نصياً للحافظة.
- السجل `LOG` داخل الشاشة يعرض كل هدف ونتيجته، والقائمة الرئيسية تعرض
  نتيجة الفحص داخل كل سطر (`🧪 ...`).

> ملاحظة: الاختبار نشاط شبكي فعلي (DNS + TCP) — التطبيق المدمج يحتاج اتصالاً
> بالإنترنت. الفاصل التلقائي يعمل فقط أثناء فتح التطبيق في المقدمة لأنه قيد
> عام لنظام iOS، وليس نقصاً في الكود.

## خيارات الكيبورد (قسم «الكيبورد» في القائمة الرئيسية)

صفّ جديد فيه زرّان، يعملان على أي حقل كتابة داخل اللعبة/التطبيق (دردشة، بحث...):

- **`تكرار الأرقام: ON/OFF`** — تكتب `135` فتصير تلقائياً `135.135`.
  أثناء الكتابة: `1` ← `1.1` ثم `13` ← `13.13` ثم `135` ← `135.135`.
  زر المسح يتراجع رقماً رقماً (`135.135` ← `13.13` ← `1.1` ← فارغ).
- **`تفكيك الحروف: ON/OFF`** — تكتب `حسين` فتصير `ح س ي ن`.
  زر المسح يمسح الحرف مع مسافته. التشكيل يبقى ملتصقاً بحرفه.

### حساسية الكيبورد (بديل كل خيارات الإرسال التلقائي القديمة)

حُذفت خيارات «ارسال تلقائي / عدد الأرقام / ارسال عند التوقف / ارسال بعد الاكمال» لأنها كانت تتعارض مع بعض.
حلّ محلها صفّان:

- **`حساسية الكيبورد: ON/OFF`** — **لا يرسل أبداً وأنت تلمس الكيبورد أو تكتب. أول ما ترفع يدك يرسل الرسالة مرة واحدة.**
  كل حرف جديد يلغي الإرسال المنتظر، والمسح كذلك. لا يتكرر الإرسال إلا إذا كتبت شيئاً جديداً.
- **`الحساسية: ذكي AUTO / 0.05s / 0.1s / 0.2s / 0.4s`** — المهلة بين رفع يدك والإرسال.
  `AUTO` = **ذكاء على الجهاز بدون إنترنت**: يتعلّم إيقاع كتابتك (الأرقام وحدها والحروف وحدها)، والمهلة = (متوسط الفاصل + 1.5 × الانحراف) × معامل تعلّم ذاتي بين 0.05 و0.35 ثانية.
  إذا أرسل مبكراً (كتبت بعده مباشرة) يبطئ قليلاً، وكلما أصاب يتسارع. يفرغ التعلّم عند تغيير الوضع أو إعادة فتح التطبيق.
- **`أقل عدد أحرف: 1/2/3/4/6/8`** — لا يرسل إلا إذا الرسالة بهذا الطول أو أطول (يمنع إرسال حرف واحد بالغلط).
- **`اهتزاز عند الارسال: ON/OFF`** — اهتزاز خفيف يؤكد لك أن الرسالة أُرسلت.

مميزات إضافية:

- ينتظر اكتمال كتابة الـ IME (الحروف العربية المعلّقة) قبل الإرسال.
- يتجاوز حقول كلمة السر وشاشات الأداة نفسها.
- يعمل مع «تكرار الأرقام» و«تفكيك الحروف» معاً (الإرسال بعد تعديلهما للنص).
- إن ضغطت Return بنفسك يلغي الإرسال المنتظر.
- إخفاء الكيبورد يلغي أي إرسال منتظر.

حدّ تقني: كيبورد iOS النظامي يعمل في عملية منفصلة ولا يمرّر اللمس للتطبيق، فالتطبيق لا يرى إصبعك مباشرة؛
لذلك يعتمد على آخر حرف أُدخل + المهلة. أما الكيبورد الذي يمر لمسه عبر نافذة اللعبة (Unity مثلاً) فيُكتشف اللمس الفعلي ولا يرسل أبداً وإصبعك عليه.
الإرسال = محاكاة زر Return/Send في الحقل (قد لا يعمل مع زر إرسال مرسوم داخل اللعبة وليس من الكيبورد).

### مرسل الأرقام (منيو مصغّر)

- زر **`مرسل الأرقام: ON/OFF`** في قسم الكيبورد. عند تشغيله يظهر **منيو صغير مستقل** فوق التطبيق.
- المنيو الصغير مستقل عن القائمة الرئيسية: **يبقى ويعمل حتى لو أغلقت القائمة القديمة بـ ✕**، ويمكن سحبه لأي مكان.
- فيه: `−` و`+` لاختيار عدد الأرقام (1 إلى 20)، وأزرار سريعة 1–6، وعدّاد حيّ `3 / 5`.
- أول ما يكتمل العدد يرسل **فوراً بدون أي تأخير (0.00s)**: رقم واحد `1` يرسل مباشرة، وإذا اخترت 5 يرسل عند `12879`.
- يعدّ الأرقام المتتالية فقط (يدعم الأرقام العربية والإنجليزية)، والحرف أو الحذف يعيد العدّ.
- ✕ في المنيو الصغير يوقف الخيار ويخفيه.
- لا يتعارض مع «حساسية الكيبورد»: إذا أرسل بالأرقام يلغي إرسال الحساسية المنتظر.

### الكتابة السريعة (رسالة واحدة لآخر حقل دردشة فتحته)

- زر **`الكتابة السريعة: ON/OFF`** في قسم «الدردشة والصوت». عند تشغيله يظهر **منيو ثالث مستقل**
  فوق التطبيق (يبقى حتى لو أغلقت القائمة الرئيسية، ويمكن سحبه).
- اكتب رسالتك في حقل المنيو واضغط **`⬆︎ إرسال`** (أو Return): تُرسَل **فوراً ومرة واحدة فقط**
  إلى **آخر حقل كتابة ضغطت فيه فعلياً داخل التطبيق نفسه** — أي الدردشة/الروم الذي أنت فيه حالياً.
- لا يستهدف أكثر من حقل واحد ولا يكرر الإرسال تلقائياً؛ كل ضغطة على «إرسال» = رسالة واحدة لوجهة واحدة.
- **تأكيد إرسال حقيقي، فوري 0.00s**: بعد الضغط على إرسال يفحص لحظياً هل تفرّغ حقل الدردشة فعلاً (كما تفعل
  كل تطبيقات الدردشة بعد نجاح الإرسال). ✅ `أُرسلت فعلاً` يعني التطبيق استلمها، ⚠️ `لم تُرسل` يعني الحقل لم
  يتفرّغ بعد وتحتاج تتحقق يدوياً — بدون أي إعادة إرسال أو تكرار تلقائي. (الفحص الفوري قد يسبق تحديث بعض
  التطبيقات البطيئة لواجهتها، فيُظهر تحذيراً رغم نجاح الإرسال فعلياً — الإرسال نفسه غير متأثر).
- إن لم تكن قد فتحت حقل كتابة في التطبيق بعد (أو أغلقته)، يظهر تنبيه «افتح حقل الدردشة واضغط فيه أولاً»
  ولا يُرسل شيء.
- لا يعمل مع حقول كلمة السر ولا مع حقول شاشات الأداة نفسها.
- الإعداد يُحفظ في `settings.json` (`quickSendOn`).

### السرعة الحية (منيو صغير ثانٍ)

- زر **`السرعة الحية: ON/OFF`** في قسم «الدردشة والصوت». عند تشغيله يظهر **منيو صغير مستقل** (يبقى حتى لو أغلقت القائمة الرئيسية، ويمكن سحبه). ✕ فيه يوقف الخيار ويخفيه.
- فيه: أزرار السرعة `x1 / x1.5 / x2 / x3 / x4`، و`⏱ تأخير` (5 / 10 / 20 / 30 ثانية)، وزر `● LIVE`، وسطر حالة حيّ (`🟢 مباشر` / `⏳ تجميع` / `🚀 لحاق`).
- **يلتقط الصوت تلقائياً من:**
  - **Agora** (صوت المتكلمين قبل الخلط، لكل متكلم على حدة) عبر محرك WSOLA يحافظ على النغمة.
  - **AVPlayer / AVAudioPlayer** (أي مشغّل صوت/فيديو أونلاين في التطبيق): تُطبَّق السرعة عليها فور تشغيلها، ويُعاد ضبطها عند تغيير الزر. ملاحظة: `AVAudioPlayer` يدعم حتى 2x فقط. صوت دخول الروم الخاص بالأداة لا يتأثر.
- **البث الحي ليس ملفاً جاهزاً:** لا يمكن سماع الكلام أسرع من وصوله. لذلك عند اختيار x2 أو أكثر: يجمع التأخير المختار **بصمت**، ثم يشغّل المتجمّع **مسرّعاً بنغمة طبيعية** حتى يلحق البث الحي، وبعدها يرجع تلقائياً 1x بلا تقطيع. اضغط **نفس زر السرعة** مرة ثانية لبدء تجميع ولحاق جديد، و`LIVE` للقفز للبث الحي فوراً.
- مثال: تأخير 20s على x2 = 20 ثانية صمت ثم نحو 20 ثانية تسريع. على x4 يلحق خلال نحو 7 ثوانٍ.
- المحرك اختُبر بمعزل عن اللعبة بإشارة تجريبية: صمت التجميع كامل، النغمة بقيت 220Hz أثناء اللحاق، والتسريع x2 فعلي.
- الإعدادات تُحفظ في `settings.json` (`liveSpeedOn` / `liveSpeed` / `liveDelay`).
- **`🌐 كل الصوت (Zego وغيره)`** (زر داخل المنيو الصغير): بما أن بعض الغرف تعمل بـ **Zego** (موجود بالـ IPA: ZegoLiveRoom / ZegoLiveRoomEngine) وليس Agora، هذا الوضع يلتفّ حول دوال تشغيل الصوت (AudioUnit render callbacks) فيعالج **المخرج النهائي** مهما كان المحرك، بنفس منطق التجميع ثم اللحاق. تنبيه: يشمل كل ما يمر بتلك الوحدة (أصوات اللعبة أيضاً) لأنه على المخرج النهائي، وعند تشغيله يتوقف مسار Agora الخاص حتى لا يُعالَج الصوت مرتين. لا يعمل إن كان المحرك يمرّر الصوت عبر AUGraph داخلياً بدل `AudioUnitSetProperty`.
- حدود: الستيريو يُدمج إلى أحادي أثناء المعالجة. إذا كان «VOICE SPEED» القديم مفعّلاً معه، تأخذ «السرعة الحية» الأولوية. أصوات الألعاب المدمجة (FMOD/Unity) التي لا تمر عبر Agora أو AVFoundation لا تُلتقط.

### الدردشة المباشرة (عميل WebSocket لسيرفرك الخاص)

- زر **`الدردشة المباشرة: ON/OFF`** في قسم «الدردشة والصوت». عند تشغيله يظهر **منيو ثانٍ مستقل**
  فوق التطبيق (نافذة منفصلة، تبقى حتى لو أغلقت القائمة الرئيسية، ويمكن سحبها).
- داخل المنيو: حقل لعنوان سيرفرك (`IP:PORT`، مثال `1.2.3.4:8080`) وزر **حفظ** يعيد الاتصال بالعنوان
  الجديد، وسجل يعرض كل رسالة تصل مع وقتها، وحالة الاتصال (متصل / يحاول الاتصال… / غير متصل).
- يتصل عبر WebSocket (`ws://`) ويعيد المحاولة تلقائياً كل 3 ثوانٍ إذا انقطع الاتصال وما زال الخيار مفعّلاً.
- يقرأ الرسائل بصيغة `{"type":"message","text":"..."}` (وأيضاً نصاً عادياً لو وصل).
- **✕** داخل المنيو يوقف الخيار ويقطع الاتصال ويخفي المنيو.
- إعداداته (تشغيل/عنوان) تُحفظ في `livechat.json` داخل مجلد بيانات الأداة.

**سيرفر تجريبي:** ملف `server/chat-server.js` في المستودع سيرفر Node.js بسيط (مكتبة `ws`) يبث أي رسالة
تصله لكل المتصلين. شغّله على جهازك أو VPS خاص بك:

```
cd server
npm init -y && npm install ws
node chat-server.js
```

ثم ضع عنوان جهازك (IP الحقيقي، ليس 127.0.0.1، إلا إذا كان الجهاز نفسه) في حقل المنيو داخل التطبيق.
هذا السيرفر **لا** يُبنى داخل الـ dylib — يعمل بشكل منفصل على حاسوبك، والتطبيق يتصل به فقط كعميل.

ملاحظات:

- الخيارات تُحفظ في `settings.json` (`kbRepeatNums` / `kbSplitLetters` / `kbSense` / `kbSenseMode` / `kbMinChars` / `kbHaptic` / `digitSend` / `digitCount`) ويعملان لحظياً بلا إعادة تشغيل.
- لا يعملان داخل شاشات الأداة نفسها (حقل البحث، رابط البروكسي...) ولا في حقول كلمة السر.
- يمكن تفعيل الاثنين معاً (الأول للأرقام والثاني للحروف).
- إن استخدمت اقتراحات الكيبورد (شريط الكلمات المقترحة) فقد تُدرَج الكلمة كاملة بدون تفكيك عبر آلية أخرى في iOS؛ عطّل الاقتراحات لنتيجة أدق.

## PROXY — اتصال عبر أي رابط بروكسي

في القائمة الرئيسية (قسم **الشبكة وDNS**) صفّ جديد فيه ثلاثة أزرار:

- **`PROXY: ON/OFF`** — تشغيل/إيقاف (يعرض عدد الاتصالات التي مرّت عبر البروكسي).
- **`PROXY LINK`** — الصق/اكتب الرابط ثم **حفظ وتفعيل** (أو **لصق من الحافظة وتفعيل**). يُختبر تلقائياً بعد الحفظ.
- **`TEST`** — يفتح نفقاً عبر البروكسي ويعرض **IP الخروج** وزمن الاتصال.

الصيغ المدعومة:

| الصيغة | مثال |
|---|---|
| SOCKS5 | `socks5://user:pass@host:1080` (أو `socks5h://` أو `socks://`) |
| HTTP (CONNECT) | `http://user:pass@host:8080` |
| رابط تيليجرام | `https://t.me/socks?server=H&port=P&user=U&pass=W` أو `tg://socks?...` |
| بدون scheme | `host:port` أو `host:port:user:pass` (المنافذ 80/8080/3128/8888... تُعامل HTTP والباقي SOCKS5) |

كيف يعمل:

- **TCP الخام** (مكتبات التطبيق التي تستدعي `connect`): تُنشأ المصافحة مع البروكسي ثم الاتصال بالوجهة. الوجهات المحلية/الخاصة (127.x, 10.x, 192.168.x...) لا تُمرَّر.
- **NSURLSession** (HTTP/HTTPS/WebSocket): يُحقن البروكسي في إعدادات الجلسات عند إنشائها (iOS 17+ مع مصادقة أصلية).
- الرابط يُحفظ في `Documents/AflatoonSuite/proxy.json` ويُفعَّل تلقائياً عند فتح اللعبة قبل أي اتصال.
- عند فشل البروكسي تفشل الاتصالات (لا تسريب مباشر) — أوقف البروكسي من الزر إن تعطّل.

حدود يجب معرفتها:

- **UDP غير مدعوم** (مثل الصوت الذي يمر عبر UDP). DNS يُحلّ محلياً قبل الاتصال.
- **vmess / vless / trojan / ss / hysteria** غير مدعومة (تحتاج نواة Xray أو sing-box).
- الجلسات التي أنشأها التطبيق **قبل** التفعيل لا تتأثر حتى إعادة فتح اللعبة، و`NSURLSession.sharedSession` لا يمكن حقنها.

## ServerTester (اختبار الضغط لسيرفرك الخاص)

في نفس شاشة `SERVER TEST`:

- **WS**: عنوان WebSocket لسيرفرك (اضغط لتعديله).
- **HTTP**: عنوان فحص صحة اختياري (اضغط لتعديله).
- **CLIENTS / DURATION / RATE**: تدوير بين قيم جاهزة (5-100 عميل، 10-120 ثانية، 1-20 رسالة/ثانية).
- **RUN NOW**: يشغّل اختبار الضغط فوراً ويطبع النتيجة بسجل الشاشة
  (`NSURLSessionWebSocketTask` + HTTP health checks)، مثل `server-tester.js` الأصلي.
- **AUTO LOAD**: يشغّل اختبار الضغط تلقائياً كل `N` دقيقة (15/30/60/120) **والتطبيق مفتوح بالمقدمة**.

استخدمه **فقط على سيرفرك الخاص**. العنوان الافتراضي وهمي
(`your-server.example.com`) ولازم تغيّره بنفسك.

## الملفات والإعدادات (داخل التطبيق)

كل شيء في مجلد واحد: `Documents/AflatoonSuite/`

| ملف | ماذا يحفظ |
|---|---|
| `settings.json` | مفتاح NextDNS + القواعد + إعدادات الصوت والدردشة |
| `server-test.json` | عنوان WS/HTTP وباراميترات اختبار الضغط |

## الدول 🚩 (جديد): علم في الشات → يكتب الاسم أو العاصمة

- صف جديد في القائمة (قسم «الدردشة والصوت»): **`الدول (علم ← اسم/عاصمة): ON/OFF`** يُظهر/يُخفي زراً عائماً صغيراً **🚩** مستقلاً عن القائمة (يظهر تلقائياً عند فتح اللعبة).
- اضغط 🚩 فتظهر لوحة صغيرة: **`🌍 اسم الدولة`** أو **`🏛 العاصمة`** (اضغط الخيار الفعّال مرة ثانية ليتوقف) و **`⏹ إيقاف`**. الاختيار محفوظ.
- إذا نزل أي شخص علماً في الشات (أو **علمين أو أكثر في نفس الرسالة**) يكتب **كل** الأسماء/العواصم بالترتيب مفصولة بمسافة، فوراً في حقل الكتابة المفتوح (بدل محتواه). مثال: 🇮🇶🇫🇷 ← `العراق فرنسا` أو `بغداد باريس`.
- **`⬆︎ إرسال: ON/OFF`** يرسل بعد الكتابة (افتراضي OFF = يكتب فقط).
- **`الرسالة: أعلام فقط / أي نص فيه علم`**: الأول لا يتحرك إلا إذا الرسالة أعلام فقط (يتجنب أعلام الملفات الشخصية)؛ الثاني يلتقط العلم حتى لو معه نص.
- يعمل فقط إذا نص الدردشة UILabel/UITextView عادي، ويحتاج حقل كتابة مفتوحاً (أو آخر حقل كتبت فيه). 196 دولة بالعربي.

## السرعة الحية: وضع «متأخر دائماً» (تعديل)

- خيارات التأخير صارت: **0.0 / 5 / 10 / 20 / 30 ثانية / 1 / 5 / 10 / 30 دقيقة** (الزر يدور عليها).
- لما تختار سرعة x1.5 أو أكثر، يبقى الصوت متأخراً عن البث الحي بمقدار التأخير المختار **ولا يرجع للبث الحي أبداً**.
  يشغّل ما فوق التأخير مسرّعاً بنبرة طبيعية على دفعات، وإذا قرب من حد التأخير يسكت قليلاً حتى تتجمع دفعة جديدة (حوالي 0.25 ث).
- **0.0** = بدون تأخير إضافي: أول صوت بعد ~0.25 ثانية فقط.
- التأخير الكبير يستهلك ذاكرة بالتدريج: 30 دقيقة ≈ 58 ميغابايت لكل متكلم بـ 16kHz (ويزيد مع التردد الأعلى).
- زر **LIVE** يقفز لأقرب بث ثم يرجع يجمع التأخير المختار.
- اختبار المحرك بمعزل: 60 ث إدخال، x2/x4 بتأخير 0 و5 ثواني؛ النبرة 300Hz بقيت 303Hz، والمدة الخارجة = المدخل ÷ السرعة تقريباً.

## تقليل تأخير الصوت + إعدادات حرة (جديد)

هدفه إزالة أكبر قدر من تأخير صوت الروم. المفاتيح مأخوذة بالاسم من `AgoraRtcKit.framework` داخل IPA يلا لودو 4.6.0 (قراءة نصوص الثنائي فقط، ما جربتها على اللعبة).

- صف جديد بالقائمة: **`تقليل تأخير الصوت: OFF / خفيف / قوي / أقصى / تجريبي / الكل (51 مفتاح)`** (يدور):
  - **خفيف**: `rtc.min_playout_delay=0` + تسريع مخزن الشبكة (`neteq.fast_accelerate` و `acceleration_percent=50`).
  - **قوي**: + سقف `rtc.max_playout_delay=300` + `audience_latency_level=2` + تصغير مخزن مكبر الجهاز (`preferredIOBufferDuration` = 10ms).
  - **أقصى**: تسريع 100 + سقف 150 + مخزن الجهاز 5ms. أقل تأخير، لكن يزيد احتمال التقطيع إذا النت ضعيف.
  - **تجريبي**: كل مفاتيح «أقصى» + 8 مفاتيح NetEQ وغيرها (قيمها مخمّنة، غير موثقة). بعد الضغط يظهر «قبلها Agora: X من Y».
  - **الكل (51 مفتاح)**: 44 مفتاح Agora (23 اتجاهها واضح من اسمها + 21 «استكشافية» قيمها تخمين، ما عدا `dump` لأنه يكتب ملفات) + **7 مفاتيح Zego** تُرسل عبر `+[ZegoLiveRoomApi setConfig:]` عند تشغيل اللعبة (تحتاج إعادة فتح اللعبة، وتخص الغرف اللي تشتغل بـ Zego فقط). للتجربة فقط؛ الرجوع: OFF ثم أعد فتح اللعبة.
- قائمة كل المفاتيح ومعانيها المتوقعة: ملف `AGORA_KEYS.md`.
- لا يمكن إلغاء تأخير الشبكة نفسه (سفر الصوت من المتكلم لجهازك)، فقط تأخير المخازن.
- للرجوع للأصلي: اختر OFF ثم أعد فتح اللعبة.
- ملف **`Documents/AflatoonSuite/agora_params.json`** (يُنشأ فارغاً `{}`): أي مفتاح تضيفه يُرسل لـ Agora عند إنشاء المحرك، مثال:
  `{"che.audio.neteq.deceleration_percent": 0}`
- مفاتيح NetEQ الأخرى الموجودة بالمكتبة للتجربة: `force_stretch`, `delay_tune`, `target_level_improve`, `accelerate.*`. معاني قيمها غير موثقة.

## شكل القائمة الجديد (كل الخيارات ظاهرة بلا سكرول)

- الأزرار صارت بـ **بطاقات أقسام** بإطار نيون متوهج وتدرّج لوني: **ادارة البيانات** (أخضر)، **الشبكة · DNS · الاختبار** (سماوي)، **الدردشة والصوت** (بنفسجي)، **الكيبورد** (ذهبي).
- داخل كل بطاقة شبكة أعمدة (حوالي زر لكل 150pt: 5 أعمدة على آيباد طولي، 3 على جوال). الصف الأخير الناقص يتمدد ليملأ العرض.
- آيباد طولي: كل شي ظاهر بدون سكرول، وقائمة النطاقات تاخذ الباقي (حد أدنى 120pt).
- جوال أو آيباد أفقي: نفس التصميم لكن داخل سكرول حتى ما ينكسر شي (قائمة النطاقات بارتفاع ثابت 220pt).
- زر SERVER TEST انتقل لبطاقة الشبكة. ما تغيّرت وظائف أي زر.

## الإرسال بعد الفاصلة (جديد)

- بالمنيو المصغّر لـ «مرسل الأرقام» زر جديد: **`النمط: عدد الأرقام / بعد الفاصلة`**.
- بنمط **بعد الفاصلة**: لحظة تكتب فاصلة ثم N أرقام يرسل فوراً (0.00s). الافتراضي N = 3 (أزرار 1..6 و − و + تغيّره).
  مثال: تكتب `7943461643464646.758`، وبمجرد ما تكتب الرقم الأخير (8) يرسل. ما يرسل قبل (`...75`)، وما يرسل إذا ما في رقم قبل الفاصلة (`.758`).
- الفاصلة المقبولة: `.` `,` `٫` `،` (الفاصلة العربية) وما يماثلها بعرض كامل، والأرقام عربية أو إنجليزية. مثال: `٢٩٣٩٣٩٩٤،٩٨٣` يرسل عند آخر رقم.
- زر القائمة الرئيسية يعرض `إرسال بعد الفاصلة: ON (.3)`. الإعدادان (النمط وN) محفوظان.
- يعمل بنفس مسار الإرسال السريع الموجود (بلا تأخير مؤقت).

- تسريع إضافي: الإرسال بنمط الفاصلة يتم **قبل** أي اهتزاز أو تحديث واجهة، والاهتزاز والتحديث يجيان بعده بدون تأخيره. يتسجل باللوق زمنان منفصلان: زمن الأداة (من وصول الرقم الأخير لحد قبل الإرسال) وزمن معالج الإرسال حق اللعبة نفسها: `decimal send: tool X ms | game send handler Y ms`. فحوصات الضغطات العادية أُخفّت: الأرخص أولاً، وفحص نوع الحقل يتم فقط لحظة الإرسال.

## مرسل الأرقام (Number Sender) — بدل «إرسال بعدد الأرقام» القديم

- حُذف الخيار القديم بواجهته، وصار مكانه صف **`مرسل الأرقام: OFF / ON (12 خانة)`** بقسم الكيبورد. تضغطه فيظهر **منيو صغير مستقل** (بتصميم Number Sender من ملف aflaton.txt) ويختفي عند الإطفاء.
- المنيو الصغير: ترويسة داكنة بخط أزرق، بطاقة حالة (عدد الخانات + يعمل/متوقف)، **الخيارات الجاهزة** (عشرات 2، مئات 3 ... مليار 10 ... تريليون 13 ... سكستليون 22)، **عدد مخصص** (1 إلى 100) مع زر تطبيق، ومفتاح **تفعيل الإرسال التلقائي** (إيقاف مؤقت مع بقاء المنيو ظاهراً). يُسحب من الترويسة، وزر ✕ يطفئ ويخفي.
- الإرسال: لحظة يكتمل عدد الأرقام المحدد (عدّاد أرقام متتالية) يرسل فوراً 0.00s، بنفس محرك الإرسال السابق.
- **نمط الفاصلة العشرية** (الذي أُضيف قبل) بقي كمفتاح داخل المنيو الصغير حتى لا تضيع الميزة: عند تفعيله يرسل بعد الفاصلة + عدد الأرقام (الافتراضي .3) وحقل «عدد مخصص» يحدد عدد الأرقام بعد الفاصلة (1 إلى 6).
- لم أنقل خيار «ضغط الماوس عند الاكتمال» من الصفحة، لأنه خاص بالمتصفح وما له مقابل على iOS.
- حقل العدد داخل المنيو الصغير مستثنى من أدوات الكيبورد (تكرار الأرقام، التفكيك، الإرسال)، فما تتداخل معه.

## فرض Zego فقط (جديد)

زر جديد بقسم «الدردشة والصوت»: **«فرض Zego فقط: ON/OFF»**.

**وش يسوي بالضبط:** لما يكون ON، يمنع Agora كلياً من الانضمام لأي قناة صوتية (`joinChannelByToken` يرجع خطأ `-2` فوراً بدون أي محاولة حقيقية، و`createRtcChannel` يرجع `nil`). الهدف: إجبار اللعبة، إذا كان عندها مسار بديل بـZego لنفس الغرفة، على استخدامه بدل Agora.

**تحذير صريح ومهم:** هذا **تخمين مبني على افتراض** أن اللعبة تملك منطق تبديل تلقائي (fallback) لـZego عند فشل Agora. ما قدرت أتأكد من وجود هذا المنطق فعلياً داخل كود اللعبة — فحصت فقط أن مكتبتي Agora وZego موجودتين معاً بالتطبيق، لكن القرار "أي واحد يُستخدم لأي غرفة" يتحكم فيه خادم اللعبة والتطبيق نفسه، مو شيء أقدر أؤكده من الـIPA وحده.

**يعني احتمالين:**
1. **لو عند اللعبة فعلاً مسار بديل:** الصوت بيشتغل عبر Zego بدل Agora، وبتشوف الفرق.
2. **لو ما عندها مسار بديل لتلك الغرفة بالذات:** الصوت بينقطع كلياً بتلك الغرفة (ما تسمع ولا تتكلم)، لأن Agora ممنوع والغرفة ما تعرف تستخدم غيره.

**جرّبه بحذر:** فعّله بروم صوتي واحد وراقب النتيجة. لو انقطع الصوت كلياً، رجّعه OFF فوراً. ما ينصح تفعيله بروم مهم أو وأنت وسط استخدام فعلي.



### PING على الشاشة

- زر **`PING على الشاشة: ON/OFF`** داخل بطاقة «الشبكة · DNS · الاختبار». عند التشغيل تظهر **شارة صغيرة فوق الشاشة** (فوق كل شي ومستقلة عن القائمة) تعرض `PING xx ms` وتتحدّث كل ثانية ونصف. تُسحب لأي مكان.
- اللون: أخضر أقل من 60ms، أصفر أقل من 120ms، أحمر أكثر من ذلك، و`PING —` عند انتهاء المهلة (2 ثانية).
- **الضغط على الشارة يبدّل الهدف:** `Cloudflare 1.1.1.1` ← `Google 8.8.8.8` ← `GAME` (آخر سيرفر TCP عام اتصلت به اللعبة، تلتقطه الأداة من `connect`). إن لم تتصل اللعبة بسيرفر بعد، يقيس نحو Cloudflare ويكتب ذلك.
- طريقة القياس: زمن مصافحة TCP (SYN ← SYN-ACK أو RST) وليس ICMP، لأن iOS لا يسمح بـ ICMP بلا صلاحيات خاصة. القياس يتم مباشرة وليس عبر البروكسي، فلو البروكسي مفعّل قد يختلف عن الزمن الحقيقي للعبة.
- ألعاب كثيرة (ومنها صوت Agora/Zego) تستخدم UDP، فبعض سيرفراتها قد لا تقبل TCP. وقتها يظهر `PING —` أو رقم لا يعكس مسار الصوت، والأدق هنا الهدفان العامان.
- الإعدادات تُحفظ في `settings.json` (`pingOn` / `pingTarget`).

### NTgCalls (تجهيز)

- ملف البناء `.github/workflows/build-ntgcalls-ios.yml`: يجلب نسخة iOS الجاهزة من إصدارات NTgCalls إن وُجدت، وإلا يحاول البناء من المصدر، ويرفع المخرجات كـ Artifact باسم `ntgcalls-ios`.

## غرف بالـ ID (جديد): دخول غرفة دردشة برقمها + منيو ثاني للكتابة والصوت

- صف جديد بقسم «الدردشة والصوت»: **`غرف بالـ ID: ON/OFF`**. عند ON يظهر منيو صغير: **رقم الغرفة** + كلمة السر (اختياري) + زر **دخول** + آخر 8 أرقام دخلتها (اضغط رقم يتعبّى) + زر **لصق** من الحافظة.
- بعد الدخول يظهر **منيو ثاني** (أو بزر 💬): تكتب رسالة وترسلها لحقل دردشة الغرفة الظاهر باللعبة. الصوت يشتغل تلقائياً بمجرد دخولك الغرفة (هذا من اللعبة نفسها).
- مأخوذ من فحص IPA: الكلاس `_TtC9YallaLudo12YallaRoomKit` (`+shared`) ودالتها `enterRoomWithRoomId:idx:ip:name:page:sessionId:pwd:` — نستدعيها كما تستدعيها اللعبة، فتبقى كل تحققات السيرفر (كلمة السر، الحظر، إغلاق الغرفة) كما هي.
- المراقبة: إن ما انفتحت الغرفة خلال 6 ثواني يجرّب صيغة ثانية (`idx=0`) مرة واحدة، ثم يعلن النتيجة. كل محاولة تُكتب في `Documents/AflatoonSuite/room_enter.log` (بدون كلمة السر).
- حدود: ما أقدر أتأكد بدون تجربة أن اللعبة تقبل `idx=رقم الغرفة` لكل الغرف؛ لو فشل أرسل لي `room_enter.log`. الإرسال يستخدم نفس محاكاة Return (إذا زر الإرسال مرسوم بالواجهة ولا يقبل Return ما يرسل).

### تحديث غرف بالـ ID: وضع التعلّم (بعد فيديو الإدخال الفاضي)

- المشكلة: إرسال رقم الغرفة وحده فتح **هيكل غرفة فاضي** (يظهر ID بدون أعضاء ولا بيانات)، لأن اللعبة تحتاج `idx` و`ip` و`sessionId` من السيرفر.
- الحل: **وضع التعلّم**. كل ما تدخل غرفة من واجهة اللعبة نفسها (قائمة، بحث، رابط...) تلتقط الأداة القيم الحقيقية وتحفظها (آخر 60 غرفة). بعدها «دخول بالـ ID» لنفس الغرفة يعيد نفس القيم الحقيقية.
- الغرف الجديدة (ما دخلتها من قبل): يجرّب مرة وحدة بقيم مخمّنة (ip من حساب اللعبة `needHostRoom:` وباقي القيم فاضية). إن ما انفتحت يقول لك تدخلها من اللعبة مرة وحدة.
- ما عاد في محاولة ثانية تلقائية (كل محاولة فاشلة تفتح هيكل غرفة فاضي).
- السجل `Documents/AflatoonSuite/room_enter.log` يكتب القيم المتعلَّمة (`تعلّمت: rid=... idx=... ip=...`) ومحاولاتك. مفيد لي لو تحتاج نضبط الصيغة للغرف الجديدة.
- الدردشة (المنيو الثاني) بقيت كما هي.

### الإرسال الفوري داخل حقل منيو الغرف

- حقل «اكتب رسالتك للغرفة» بالمنيو الثاني صار يدعم **الإرسال الفوري** (مرسل الأرقام): لما يكتمل عدد الأرقام المحدد، أو فاصلة + N أرقام بنمط الفاصلة، يرسل الرسالة فوراً لحقل دردشة الغرفة ويمسح الحقل.
- شرطه: خيار «مرسل الأرقام» شغّال (ON). سطر التلميح تحت الحقل يوضح الحالة: `⚡ إرسال فوري: يرسل عند 12 أرقام` أو `فاصلة + 3 أرقام`.
- بقية أدوات الكيبورد (تكرار الأرقام، تفكيك الحروف) ما تشتغل بهذا الحقل، فقط الإرسال الفوري.

### الإرسال الفوري بحقل «رقم الغرفة»

- حقل رقم الغرفة بالمنيو الأول يدعم الإرسال الفوري: لما يكتمل عدد الأرقام المحدد بـ«مرسل الأرقام» (نمط عدد الخانات) يضغط **دخول** تلقائياً. اضبط العدد على طول رقم الغرفة (مثلاً 6 أو 7) من منيو مرسل الأرقام.
- إذا غرفتك بكلمة سر، اكتب الكلمة أولاً بحقلها ثم رقم الغرفة، لأن الدخول يتم لحظة اكتمال الرقم.
- نمط الفاصلة العشرية ما يشتغل بهذا الحقل (الأرقام ما فيها فاصلة). سطر الحالة تحت الأزرار يوضح الوضع.

### دردشة الغرفة: الأحدث بالأعلى

- زر **`دردشة الغرفة: الأحدث بالأعلى: ON/OFF`** في بطاقة «الدردشة والصوت».
- قائمة الرسائل في غرف يلا لودو هي `YLRoomKit.YLRoomMessageTableView` (UITableView بمصدر بيانات `YLRoomMessageDiffableDataSource`، خلاياها `YLRoomTextMessageCell` وغيرها). تم استخراج الاسم من الـ IPA.
- الأداة تقلب هذي القائمة عمودياً (`scaleY = -1`) وتقلب كل خلية وترويسة مرة ثانية، فيظهر النص طبيعياً لكن الأحدث فوق. وتضيف `contentInset.top` بقدر الفراغ عندما تكون الرسائل قليلة، فتبقى الرسائل **ملتصقة بأعلى** منطقة الدردشة مثل الوضع العادي، والأحدث أولاً.
- مثال: ترسل `1` ثم `2` فتظهر `2` فوق `1`.
- عند OFF يُرجَع كل شي (القلب والـ inset الأصلي).
- ملاحظة: كلاس الجدول مأخوذ من أسماء الـ IPA الحالي (`4.6.0`). إن تغير الاسم بتحديث للعبة يحتاج تعديل `DSIsChatTable`.

### إرسال فوري بالإنتر في دردشة الغرفة

- زر **`إرسال فوري بالإنتر (دردشة الغرفة): ON/OFF`** في بطاقة «الدردشة والصوت».
- مربوط بصندوق كتابة الغرفة الحقيقي `YLRoomInputView` (من الـ IPA): عند الضغط على Enter، الأداة تستدعي زر الإرسال الرسمي `sendButtonClicked:` مباشرة بدل انتظار أي معالجة وسيطة، فيصير الإرسال بأقصر مسار ممكن.
- **تعديل على جهازك فقط.** لا يغيّر أي شي بالسيرفر ولا بترتيب الرسائل عند الآخرين، ولا يمنحك أولوية إرسال حقيقية على بقية اللاعبين (مين وصل للسيرفر أولاً يحدده السيرفر نفسه، مو الشاشة).
- لا علاقة له بميزة «الأحدث بالأعلى» (تلك تغيّر شكل عرض القائمة فقط، وهذه تسرّع لحظة الضغط على إرسال).

### تبسيط المنيو (بناءً على طلب)

تم تقليص المنيو الرئيسي ليعرض فقط:
- بطاقة «الدردشة والصوت»: تقليل تأخير الصوت، فرض Zego فقط، إرسال فوري بالإنتر.
- بطاقة «الكيبورد»: تكرار الأرقام، تفكيك الحروف، **تكرار الكلام** (جديد)، **تفكيك وعادي** (جديد)، ومرسل الأرقام (الزر يفتح منيوه الصغير كما هو).

**ملاحظة مهمة:** هذا تبسيط لواجهة المنيو فقط. الكود الخاص بالميزات الأخرى (PING، السرعة الحية، الدردشة المباشرة، الكتابة السريعة، DNS/بروكسي، إدارة البيانات، server test، NTgCalls، الدول، غرفة معينة، JOIN SOUND، VOICE SPEED القديم) **ما زال موجوداً بالملف لكنه غير معروض** ولا يظهر له زر، وإعداداته الافتراضية OFF فلا يعمل تلقائياً. حذفه بالكامل من الكود يحتاج مراجعة أعمق لتفادي كسر البناء؛ إذا تريد حذفه فعلياً (لا مجرد إخفاءه) قل لي وأكمل ذلك في جولة لاحقة.

### تكرار الكلام

- زر **`تكرار الكلام: ON/OFF`** في بطاقة «الكيبورد».
- نفس فكرة «تكرار الأرقام» لكن على الكلمات بفاصل مسافة بدل نقطة: تكتب كلمة ثم مسافة، فتتكرر الكلمة فوراً. مثال: `حسين` ثم مسافة → `حسين حسين`، ثم تكمل `احمد` → `حسين حسين احمد`.
- كل كلمة تكتبها (يتبعها مسافة) تتكرر بنفس الطريقة، وليس أول كلمة فقط.
- الحذف (Backspace) يرجع الكلمة المكررة لحالتها الأصلية تدريجياً، بنفس منطق تكرار الأرقام.

### تفكيك وعادي

- زر **`تفكيك وعادي: ON/OFF`** في بطاقة «الكيبورد».
- يختلف عن «تفكيك الحروف» (الذي يستبدل الكلمة بالكامل). هنا: تكتب الكلمة كاملة، وعند المسافة بعدها تُضاف نسخة مفكّكة منها بجانبها، وتبقى الكلمة الأصلية كما هي. مثال: `حسين` ثم مسافة → `حسين ح س ي ن `.
- ينطبق على كل كلمة تكتبها بنفس الطريقة.
- لا يحتاج معالجة خاصة عند الحذف لأن كل الأحرف المضافة حقيقية (حذف عادي حرف بحرف).
